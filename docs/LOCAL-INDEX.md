# 自前インデックス（ローカル BM25）

RustXNG は上流エンジンに依存しない**自前の全文検索インデックス**を持てます。インデックスに十分なページがあれば、上流へ投げずに**ミリ秒で**応答します。

## 構成

```text
rustxng-index crawl   →  Tantivy インデックス（BM25）
                            ↓
rustxng（--port 8888）  →  高速パス（関連度ゲート）→ 即答
                            ↓ 不足時のみ
                        175 の上流エンジンへファンアウト
```

- **転置インデックス**: Tantivy（Rust 製の Lucene 相当。BM25 でスコアリング）
- **二重トークナイズ**: 空白区切り言語は既定トークナイザ、日本語・中国語は**文字バイグラム**（分かち書きが無いため）
- **礼儀**: robots.txt の `Disallow` を尊重、同一ホストのみ辿る、リクエスト間隔を空ける、50 ページごとにコミット（途中終了でも取得済みを保持）
- **読み書き分離**: クロール中でも検索側は読み取り専用で開ける（書き込みロックを奪わない）

## 使い方

```bash
# 1. シードを用意（1 行 1 URL）
cat > seeds.txt <<'EOF'
https://doc.rust-lang.org/book/
https://docs.python.org/3/library/
EOF

# 2. クロール（robots.txt を尊重し、350ms 間隔）
rustxng-index crawl --seeds seeds.txt --out ./index-data --max-pages 2000 --max-depth 2 --delay-ms 350

# 3. 確認
rustxng-index stats --index ./index-data
rustxng-index search --index ./index-data "python dict get" --limit 5

# 4. サーバーで有効化
```

```toml
# settings.toml
[search]
local_index_path = "./index-data"
local_index_min_hits = 3      # これ未満なら上流へフォールバック
local_index_min_score = 6.0   # 最上位ヒットの最低 BM25 スコア
```

## 高速パスの安全性

「ヒット数が多ければ即答」では不十分でした。薄いインデックスでも 3 件は必ず返るためです。現在は**自前の関連度モデルで最終判定**し、`relevance >= 0.75` のときだけ即答します。

実測（600 ページのインデックス、100 問）:

| 設定 | hit@1 | hit@5 | MRR | レイテンシ | 即答数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| インデックスなし | **79** | **92** | **0.853** | 933〜1,035 ms | 0 |
| ゲートなし | 38 | 44 | 0.404 | **0.7 ms** | 98 |
| 関連度 0.5 | 59 | 65 | 0.623 | 0.8 ms | 67 |
| **関連度 0.75（既定）** | 78 | 86 | 0.824 | **611 ms** | 73 |

**速度は Exa 並み（611 ms 対 598 ms）になりますが、hit@5 と MRR が落ちます。** 即答した 73 問はローカル結果だけを返すため、インデックスに無いページは拾えないからです。**インデックスが実用サイズになれば、この差は解消されます。**

### 既定は無効

`local_index_path` の既定は空です。インデックスが小さいうちは高速パスが精度を下げるため、**自分でクロールして十分なページを入れたときだけ有効化**してください。

## 現状の制約（正直なところ）

- 同梱のデモインデックスは 600 ページで、評価セットのトピックからシードして構築しました。**本番のインデックスはもっと広いクロールが必要**です
- Wikipedia は全文クロールが非現実的なため、記事 URL を直接シードしています
- クロールは単一プロセス・逐次です（並列化と差分更新は未実装）
