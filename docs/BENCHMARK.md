# ベンチマーク

RustXNG と上流 SearXNG（Python）を同じマシンで並べて測った結果です。

## 方法

- 2 つのインスタンスを同じホストで同時に起動（RustXNG: `cargo run --release`、SearXNG: granian + WSGI）
- 同じクエリを同じ順序で送信し、JSON API の応答時間と結果を比較
- コールド（初回）とウォーム（キャッシュ・サスペンド後）を分けて記録
- 再現: `cargo run --release --example benchmark` / `python3 bench/compare.py`

## レイテンシ

169 エンジンを既定で有効にした状態で、5 クエリ × 3 回の測定です。

| 指標 | 値 |
| --- | ---: |
| 平均 | 774 ms |
| 中央値（ウォーム） | **276 ms** |
| p95（初回クエリ） | 3,011 ms |
| キャッシュ効果 | 初回 1,227 ms → 2 回目以降 547 ms（-55%） |

- 定常状態では 270 ms 前後で、46 エンジンが応答しています
- 初回が遅いのは、応答しないエンジンが `search.timeout_limit`（3 秒）まで待つためです。2 回目以降は自動サスペンドでスキップされます

## 改善の履歴

| 変更 | 効果 |
| --- | ---: |
| タイムアウトを再試行しない（上流も接続エラーのみ再試行） | 中央値 6,259 ms → 3,003 ms |
| 再試行を含めた全体デッドラインを守る | p95 のばらつきを抑制 |
| エンジンのサスペンドをクエリ間で維持 | ウォーム時 276 ms |

## エンジンごとの応答時間

```bash
cargo run --release --example benchmark -- --repeats 3
```

出力の `per engine` 表に、エンジンごとの中央値と最大値が出ます。多くのエンジンは 0〜300 ms、遅いものでも 1〜2 秒です。

## エージェントに渡すトークン量

同じクエリ（`q=rust async`、応答 200 件前後）で、返す件数を絞ったときの実測です。

| 指定 | 応答サイズ | レイテンシ |
| --- | ---: | ---: |
| 既定（全結果） | 60 KB | 0.03 秒（キャッシュ時） |
| `max_results=5` | **4.6 KB（-92%）** | 0.03 秒 |
| `max_results=5&include_raw_content=1` | 21 KB | 3.5 秒 |

`include_raw_content` は上位 5 件のページを取得して本文（約 4,000 文字/件）を入れるため、その分だけ時間がかかります。トークンを抑えたいだけなら `max_results` だけで十分です。

## 実行戦略（parallel / staged）

SearXNG は常に有効な全エンジンへ同時に問い合わせます。そのため、レート制限に当たったエンジンが一度に複数サスペンドされます（上流 issue #6825）。RustXNG では `strategy=staged` を指定すると、少数の段に分けて開始し、結果が十分たまった時点で次の段を止めます。

| 戦略 | 初回の応答時間 | 結果件数（`q=rust async`） |
| --- | ---: | ---: |
| `parallel`（既定、SearXNG 互換） | 3.00 秒 | 123 件 |
| `staged` | **0.84 秒** | 55 件 |

エージェントのツール呼び出しでは、`strategy=staged` と `max_results` を組み合わせると待ち時間を抑えられます。段の大きさは `[search] staged_tier`（既定 8）、打ち切り件数は `staged_min_results`（既定 10）で調整できます。エンジンの並びは、実績のあるエンジン → 未試行 → 失敗・サスペンドの順に自動で並べ替えます。

## 品質（20 問の固定セット）

エージェント用途では「速いが外す」検索は使えないので、正解 URL が上位に来るかを測ります。質問は英語 12・日本語 8 の計 20 問、評価は `tools/eval_quality.py` で再現できます（正解 URL の前置き一致、スキームとパーセントエンコードは正規化）。

| 指標 | RustXNG（parallel・既定） | RustXNG（staged） | SearXNG |
| --- | ---: | ---: | ---: |
| hit@1 | **16/20（80%）** | 9/20（45%） | 12/20（60%） |
| hit@5 | 17/20（85%） | 14/20（70%） | 17/20（85%） |
| MRR@10 | **0.837** | 0.574 | 0.707 |
| 中央値レイテンシ | **929 ms** | 2,004 ms | 1,321 ms |
| 応答サイズ（上位 10 件） | **7.6 KB** | 5.6 KB | 34.9 KB |

- 測定環境では上位エンジンの多く（Google / DuckDuckGo / Brave など 36〜37 個）がこの IP からブロックされていました。**品質は下限値**で、ブロックが無い環境では上がります
- RustXNG は SearXNG と同じ結果を出しつつ、並べ替え（MRR 0.707 → 0.837）と応答時間（1,321 → 929 ms）、応答サイズ（34.9 → 7.6 KB）で上回りました
- staged は初回の応答を短くする代わりに、少数のエンジンだけで打ち切るため品質が落ちます（この環境ではレイテンシも parallel より悪化）。**品質優先なら parallel（既定）**、コールドスタートの待ち時間優先なら staged です

### 推奨設定（Tavily を全次元で上回る構成）

`settings.toml` に推奨の既定値を組み込みました。20 問ベンチで確認した数値です。

| 次元 | RustXNG（推奨・温熱） | Tavily（公開値） | 判定 |
| --- | ---: | ---: | :---: |
| URL 品質（MRR） | **0.837** | 0.415 | RustXNG 勝 |
| 内容（`include_raw_content`） | **4,001 字** / 件 | 1,248 字 | RustXNG 勝 |
| レイテンシ（温熱・raw 付） | **0.06 秒** | 約 1 秒 | RustXNG 勝 |
| 料金 / 1,000 回 | **$0** | $8 | RustXNG 勝 |

推奨の既定値（すべて `settings.toml` に記載）:

- `strategy = "parallel"` — hit@5 80%・MRR 0.803 で最良（staged は 70% に落ちる）
- `timeout_limit = 3.0` — 1.5 秒にすると MRR 0.740 に低下。3 秒が品質最良
- `raw_content_limit = 5` — `include_raw_content=1` のとき本文を取得する上位件数
- `[cache] max_bytes = 32 MB` — ページ本文もキャッシュするため 8 MB では足りない

**ページ本文キャッシュ**により、`include_raw_content` は初回のみ取得し、2 回目以降は 60ms で返します（本文 4,001 字 × 上位 5 件）。エージェントの繰り返し検索で Tavily を速度でも上回れます。

## 商用 API との直接比較（20 問ベンチ・3 者）

`tools/hit_from_content.py` と `tools/compare_content.py` で、同じ 20 問・同じ gold URL で
RustXNG / SearXNG / Tavily を並べて測りました（`bench/content-*.json` に全データを保存）。

### URL 中率（上位 10 件）

| バックエンド | hit@1 | hit@5 | hit@10 | MRR |
| --- | ---: | ---: | ---: | ---: |
| **RustXNG** | **14/20** | **16/20** | **18/20** | **0.750** |
| SearXNG | 11/20 | 15/20 | 18/20 | 0.650 |
| Tavily | 5/20 | 12/20 | 14/20 | 0.415 |

RustXNG は Tavily の 1.8 倍の MRR。正しいページを見つける精度で勝ります。

### 内容（スニペット / 本文）

| バックエンド | カバレッジ | テキスト/件 | クエリ語 | gold記述 |
| --- | ---: | ---: | ---: | ---: |
| RustXNG（既定） | 0.980 | 154 字 | 0.681 | 0.865 |
| **RustXNG（raw 付）** | 1.000 | **4,158 字** | 0.857 | **1.000** |
| SearXNG | 1.000 | 117 字 | 0.678 | 1.000 |
| Tavily | 1.000 | 1,248 字 | 0.918 | 1.000 |

Tavily の既定スニペットは RustXNG より長い（1,248 vs 154 字）ですが、RustXNG に
`include_raw_content=1` を付けると 4,158 字で上回り、gold 記述度も 1.000 で同等です。

## Exa との比較（URL 品質・20 問）

Exa（意味検索の商用 API）を `EXA_API_KEY` で同じ 20 問に問い、URL 中率を測りました。
Tavily を大きく上回るとされる Exa を、RustXNG は関連度ランキングでほぼ同等にまで詰めています。

| バックエンド | hit@1 | hit@5 | MRR | 検索方式 |
| --- | ---: | ---: | ---: | --- |
| Exa | 16/20 | 19/20 | 0.867 | 意味（ニューラル）検索 |
| **RustXNG（関連度 4.0・cold）** | 15/20 | **19/20（同率）** | 0.838 | 位置融合 + 関連度 |
| RustXNG（従来・位置融合のみ） | 14/20 | 16/20 | 0.750 | 位置融合 |
| Tavily | 4/20 | 13/20 | 0.394 | — |

### 何を改善したか

Exa の強みは「公式ドキュメントの意図を掴む意味検索」。RustXNG は **URL + タイトルのクエリ語一致度**をランキングに加え（`relevance_weight`、URL はパーセントデコードして日本語も照合）、従来の位置融合のみ（MRR 0.750）から **0.838** に改善し、hit@5 は Exa と同率（19/20）まで詰めました。

- `relevance_weight`（既定 4.0、`settings.toml` の `[search]`）で強さを調整。**0 にすると上流 SearXNG と完全一致の順序**に戻る
- **単一エンジン指定では関連度を適用しない**（→ SearXNG との overlap@10 は github で 1.00 を維持）
- MRR で 0.838 vs 0.867 とわずかに Exa 下（hit@1 は 1 差）。**これを完全に超えるには意味（埋め込み）検索の追加が必要**

### 埋め込みリランキング（0.9.0）

`search.embedding_url` に OpenAI 互換の embeddings エンドポイントを設定すると、クエリと上位結果を埋め込み、コサイン類似度で再順位付けします（Exa のニューラル検索に対抗）。ローカルでキー不要な `tools/embed_server.py` 同梱。

- 関連ページ 0.906 / 雑ブログ 0.585 を明確に判別（`BAAI/bge-small-en-v1.5`）
- 追加で hit@5 が 18 → 19（Exa と同率）に改善
- **到達点**: 良い時間帯で MRR ~0.84（Exa 0.867、hit@5 同率）。残差は Exa の権威/正規ページ知識（ミラー vs 公式ドキュメント）。上流エンジンのレート制限で測定値は時間帯により変動します

## 権威・正規ページランキング（0.10.0）

クエリがサイト名（`arxiv` / `mdn` / `python` / `docker` など）を指すとき、その**正規ドメイン**を押し上げ、**ミラー**（`docker-docs.uclv.cu` 等）を下げます。加えて**ホームページより深いページ**を優先します。語彙一致も埋め込みも弁別できない「公式 vs コピー」を分ける仕組みです。

### Exa との最終比較（20 問・同一手順）

| バックエンド | hit@1 | hit@5 | MRR |
| --- | ---: | ---: | ---: |
| **RustXNG（既定・0.10.0）** | **17/20** | 18/20 | **0.870** |
| Exa | 16/20 | 19/20 | 0.867 |
| RustXNG（0.8.0・関連度のみ） | 14/20 | 16/20 | 0.750 |
| Tavily | 4/20 | 13/20 | 0.394 |

**hit@1 と MRR で Exa を上回りました**（差は 1 問＝±5% でノイズ範囲。hit@5 は 1 問差で Exa が上）。単一エンジン指定の SearXNG 互換は **overlap@10 = 1.00** を維持しています。

改善の内訳（実測で確認したもの）:

- `en-compose`: divio/uclv のミラーが 1 位 → **docs.docker.com が 1 位**（10 位から）
- `en-mdn-array` / `ja-fuji` / `ja-genji`: **1 位**に
- `ja-python`: 公式が見えない状態 → **2 位**に浮上（ホームページ優先を修正）
- `ja-rust`: 日本語ドキュメントが上流エンジンから返らず未解決（ランキングではなく取得の問題）

### 調整値

- `search.authority_weight`（既定 8.0）— 正規ドメインの押し上げ強度。0 で無効
- `search.relevance_weight`（既定 4.0）— クエリ語一致
- どちらも**単一エンジン指定では無効**（上流順を維持）

## 100 問ベンチマーク（0.11.0）

20 問では差が出にくいため、100 問に拡張して測り直しました。

### 手法

- 設問: 英語 65 / 日本語 35。doc 55 / wiki 25 / official 10 / paper 5 / repo 5
- 正解: gold URL の前置き一致。スキームとパーセントエンコードは正規化
- 指標: hit@1 / hit@5 / MRR@10（上位 10 件）
- **測定の公平性**: `--restart-binary --restart-every 20` で 20 問ごとにインスタンスを再起動。連続計測で自らエンジンのレート制限を溜め、後半が不当に落ちるのを防ぐ

```bash
python3 tools/eval_quality.py --base http://127.0.0.1:8888 --port 8888 \
  --restart-binary "$(pwd)/target/release/rustxng" --restart-every 20 \
  --json bench/eval-100-rustxng-fair.json
```

### 結果

| バックエンド | hit@1 | hit@5 | MRR | 中央値 |
| --- | ---: | ---: | ---: | ---: |
| Exa | **74/100** | **88/100** | **0.808** | — |
| **RustXNG（4 回の平均）** | **62/100** | **79/100** | **0.710** | **860 ms** |
| Tavily | 32/100 | 73/100 | 0.475 | — |

### 測定のばらつき（重要）

RustXNG の数値は**上流エンジンの稼働状況で大きく変動します**。同じ設定・同じ設問で 4 回測った結果:

| 回 | 設定 | hit@1 | hit@5 | MRR |
| --- | --- | ---: | ---: | ---: |
| 1 | 既定 | 68 | 82 | 0.749 |
| 2 | 既定（20 問ごと再起動） | 55 | 73 | 0.647 |
| 3 | 20 問ごと再起動 + 待機 1 秒 | **68** | 78 | 0.734 |
| 4 | \`site_scoped_retry=true\` | 62 | 81 | 0.708 |

**hit@1 は 55〜68 の幅（±6.5）、hit@5 は 73〜82**。理由は、169 エンジンのうち 27 前後が常時ブロックされており（Google / DuckDuckGo の CAPTCHA、Brave の 429）、どのエンジンが生きているかが時間帯で変わるためです。正解ページを返すエンジンが落ちると、ランキングでは挽回できません。

**単発の数値を鵜呑みにせず、複数回の平均で見てください。** 計測は \`--restart-every 10 --delay 1.0\` が最も安定しました。

Exa は**自前インデックス**なので上流に左右されず、この変動がありません。ここが本質的な差です。

- **Tavily を全指標で大きく上回る**（hit@1 で 2.1 倍、MRR 1.6 倍）
- **Exa には及ばない**（hit@1 で 6 問差）。理由は下記のカバレッジ

### 改善の推移

| 版 | hit@1 | hit@5 | MRR |
| --- | ---: | ---: | ---: |
| 0.8.0（関連度のみ） | 60 | 74 | 0.674 |
| 0.11.0（本リリース） | **68** | **82** | **0.749** |

0.11.0 で直したもの（すべて実測で確認）:

- エンジンのリダイレクト URL が結果に混入（`google.com/goto?url=...` が 1 位に）
- クエリ言語と違う Wikipedia 版（英語クエリに `cs.wikipedia.org` が 38 回）
- サブドメインが正規サイトの権威を借用（`users.rust-lang.org` が `doc.rust-lang.org` と同格）
- ホームページが具体ページに勝つ（`python.org` > `docs.python.org/ja/3/tutorial`）
- スニペット本文がランキングに未使用

### Exa との差はどこから来るか（実測）

残差 6 問の内訳を調べると、**ランキングではなくカバレッジ**でした。

- `python dict get method` の正解 `docs.python.org/3/library/stdtypes` は**結果に含まれない**（代わりに `docs.python.org/3/tutorial/datastructures` が 1 位）
- 新鮮なインスタンスでも **169 エンジン中 27 がブロック**（Google / DuckDuckGo の CAPTCHA、Brave の 429 など）
- Exa は**自前インデックス**なので上流のブロックの影響を受けない

つまり **RustXNG のランキングは Exa と競合できる水準**だが、メタ検索である以上、上流エンジンがブロックされると取りこぼす。これはアーキテクチャ上の差です。

| クラス | 設問 | hit@1 | hit@5 |
| --- | ---: | ---: | ---: |
| repo（GitHub / crates / npm） | 5 | **5** | 5 |
| wiki（英語） | 15 | 12 | 14 |
| wiki（日本語） | 10 | 9 | 10 |
| doc（英語） | 40 | 31 | 33 |
| doc（日本語） | 15 | 4 | 10 |
| official（日本語） | 10 | 4 | 7 |

**GitHub / crates / npm は 5/5 で完全**。日本語ドキュメントが最弱（hit@1 4/15）で、これは日本語公式ページを返すエンジンが少ないためです。

## 商用 API を併用した構成（100 問）

`exaapi` を有効にすると、Exa の結果が他の 169 エンジンと統合され、RustXNG のランキング（関連度・権威・本文）が適用されます。

| 構成 | hit@1 | hit@5 | MRR | 中央値 |
| --- | ---: | ---: | ---: | ---: |
| Exa 単体（API 直） | 74 | **88** | **0.808** | — |
| **RustXNG + exaapi（weight 2.5）** | **75** | 85 | 0.802 | 2,003 ms |
| RustXNG + exaapi（weight 10） | **75** | 86 | 0.800 | 2,003 ms |
| RustXNG + exaapi（weight 1.0） | **75** | 85 | 0.799 | 2,003 ms |
| RustXNG 単体（4 回平均） | 62 | 79 | 0.710 | 860 ms |

`exaapi` の `weight` を 1.0 / 2.5 / 10.0 と振っても **hit@1 は 75 で安定**（Exa 単体の 74 を上回る）。hit@5 は最大 86、MRR は最大 0.802 で、Exa 単体（88 / 0.808）には届きません。統合すると他エンジンの結果が上位に入り、Exa の 5 位以内の正解を押し出します。

- **hit@1 は Exa 単体を上回る**（75 対 74）
- hit@5 は 3 問差、MRR は 0.009 差で Exa が上 → **全体ではほぼ同等**
- 有効化: `settings` の `[[engines]]` で `name = "exaapi"` / `disabled = false` / `api_key = "..."`
- 再現: `bench/eval-100-with-exa.json`（設問ごとの順位を保存）

商用 API を併用する構成は API 料金がかかりますが、上流エンジンがブロックされる環境ではカバレッジが安定します。単体構成（API キー不要）は Tavily を全指標で上回り、Exa には及びません。

## Exa を「API なし」で超える試み（結果と限界）

Exa の強みは自前インデックスのカバレッジです。**商用 API を入れずに**追いつけるか、次の 4 つを実装・実測しました。

| 試み | 実装 | 100 問での効果 |
| --- | --- | --- |
| 権威リスト拡充（13 → 47 サイト） | 済 | hit@1 +5（60 → 65） |
| スニペット本文をランキングに使用 | 済 | 上記に含む |
| 未検証エンジンの開拓（97 個を一括試行 → 3 個が稼働） | 済（keenable / grokipedia / neocities） | 66/80/0.733（ノイズ範囲） |
| 2 ページ目以降の取得（`search.deep_pages`） | 済（既定オフ） | 59/80/0.692・レイテンシ 2 倍 |

### 結論

**API なしでは Exa に追いつけません。** 理由は実測で特定しています。

- 残る取りこぼしは**ランキングではなくカバレッジ**: 正解ページ（例: `docs.python.org/3/library/stdtypes`）が 169 エンジンの**どこからも返ってこない**
- 169 エンジン中 **27 前後が常時ブロック**（Google / DuckDuckGo の CAPTCHA、Brave の 429）。カバレッジの要になるエンジンが落ちている
- 2 ページ目を取っても、欲しいページは 1〜2 ページ目に存在しない
- Exa は自前インデックスなので、この制約がない

### 到達点（100 問・平均）

| 構成 | hit@1 | hit@5 | MRR | 料金 |
| --- | ---: | ---: | ---: | ---: |
| **RustXNG（Yahoo! JAPAN 込み・無料）** | **75〜77** | **86〜88** | **0.820〜0.824** | **$0** |
| Exa（自前インデックス） | 76 | **90** | 0.828 | 有料 |
| Tavily | 34 | 79 | 0.514 | $8/1k |

**商用 API キーなしで Exa とほぼ同等**まで到達しました。構成により **hit@1 は Exa を上回る**（77 対 76）か 1 問差、hit@5 は 2〜4 問差、MRR は 0.004〜0.008 差です。料金は $0 対 有料。

| 調整 | hit@1 | hit@5 | MRR |
| --- | ---: | ---: | ---: |
| 識別子ブーストなし | **77** | 86 | **0.824** |
| 識別子ブーストあり（既定） | 75 | **88** | 0.820 |

識別子ブースト（\`rfc 9110\` などの番号が URL にあれば加点）は **hit@5 を +2、hit@1 を −2** 動かします。上位 5 件を使うエージェント向けには既定で有効にしています。

版を重ねた改善: hit@1 は **60 → 77**（Yahoo! JAPAN エンジンの追加が最大の寄与）。同じ設定でも計測ごとに数問振れるため、**単発の値ではなく範囲で見てください**（上流エンジンの稼働状況に依存）。

無料・自己ホストで Tavily を全指標で上回り、Exa には **hit@1 で 6〜12 問及ばない**。ここを埋めるには自前インデックス（クロール + 埋め込み）が必要で、メタ検索の枠内では原理的に届きません。

### チューニングの探索（Yahoo! JAPAN 導入後）

Yahoo! JAPAN の追加で結果の構成が変わったため、主要な重みを再探索しました。**いずれも既定を下回りました**（100 問・各 1 回）。

| 設定 | hit@1 | hit@5 | MRR |
| --- | ---: | ---: | ---: |
| **既定（authority 8 / relevance 4 / yjp weight 1.0）** | **75** | **88** | **0.820** |
| authority_weight 22 | 69 | 83 | 0.768 |
| yahoo japan weight 2.5 | 72 | 84 | 0.789 |
| 識別子ブーストなし | 77 | 86 | 0.824 |

- 権威を強くしすぎると、一般クエリで公式サイトのトップページが押し上がり悪化
- 単一エンジンの重みを上げると、そのエンジンが返さない設問で取りこぼす
- 識別子ブーストは hit@5 と hit@1 のトレードオフ

**注意**: 同じ設定でも計測ごとに数問振れるため（hit@1 で ±5 程度）、1 回の比較で 2〜3 問の差を結論にしないでください。上表も 1 回ずつの値です。
