# 課題の解決と測定（2026-11-05）

この文書は、プロバイダー利用条件の監査・Standard の再構成・API プロファイル・MCP のトークン上限について、実測とともにまとめる。

## プロバイダー利用条件の監査

Standard で有効な未審査プロバイダー 104 件について、一次資料（規約・公式 API 文書）から利用条件を取得した。記録は `docs/audit/2026-11-05/` にある。

- 許可（条件付き）: 文書化された API。帰属・送信間隔・商用範囲などの条件を記録
- 無効提案: 内部エンドポイント、登録必須、書面同意なしの取得禁止など
- 審査継続: 規約頁が取得できない（JS 描画・403/404）もの。**既定無効**

`settings.toml` はこの結果を反映し、有効 34 エントリに `search.engine_allowlist` を設けた。`tools/check_provider_policy.py` が、有効な全エントリに記録済みの条件付き審査があることを検証する。審査は条件の記録であり、法的な許諾の確定ではない。

## MCP のペイロードとトークン上限

同じ検索結果 100 問を、生の HTTP JSON と compact 形式で比較した。

| 形式 | 中央値バイト | 中央値トークン (cl100k_base) |
| --- | ---: | ---: |
| 生の JSON | 9,978 | 2,429 |
| compact | 6,433 | 1,542 |

compact 形式はバイト数を約 36% 減らし、URL と先頭 80 文字を保持する。トークン計数は `cl100k_base` / `o200k_base` を明示した場合に提供し、対象は structured JSON に限定する。
