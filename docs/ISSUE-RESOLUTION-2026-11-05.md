# 課題の解決と測定（2026-11-05）

この文書は、2026年11月5日のプロバイダー監査、Standardの再構成、当時の有料APIを使った実験、MCPの出力上限について、保存済みの測定結果とともに記録したものです。現行v0.30.0の再測定ではありません。現在の起動プロファイルは`standard`・`clean`・`full`の3種類で、旧`api`プロファイルは廃止されています。

## プロバイダー利用条件の監査

Standard で有効な未審査プロバイダー 104 件について、一次資料（規約・公式 API 文書）から利用条件を取得した。記録は `docs/audit/2026-11-05/` にある。

- 許可（条件付き）: 文書化された API。帰属・送信間隔・商用範囲などの条件を記録
- 無効提案: 内部エンドポイント、登録必須、書面同意なしの取得禁止など
- 審査継続: 規約頁が取得できない（JS 描画・403/404）もの。**既定無効**

`settings.toml` はこの結果を反映し、有効34エントリの取得先と用途を記録した。`tools/check_provider_policy.py` が、有効な全エントリに記録済みの条件付き審査があることを検証する。審査は条件の記録であり、法的な許諾の確定ではない。

## 旧API併用構成の重み調整（追加測定・現在のFullとは別）

監査と並行して、Exa の重みと関連度ボーナスの調整を 13 回測った（`docs/audit/2026-11-05/exa-tuning-2026-11-05.md`）。

- ホワイトリスト＋Exaを組み込んだ実験構成（44エンジン・`exaapi weight=2.0`・`relevance_weight=2.0`）: hit@1は79 / 77、hit@5は92 / 92、MRR@10は0.849 / 0.839。Exa単独の保存済みhit@5=91とは測定日時が異なり、独立した同時比較でも未見設問での評価でもありません。**無料のStandard単独がExaを上回った結果ではありません。**
- 公式サイトの言語版の対応（`src/official.rs`）と、多ホスト索引の 1 ホスト上限 3 件（`src/aggregator.rs`）を含む
- 追加の重み調整は既知の100問を使った探索で、上表の固定条件による反復と区別する
- tavily エンジンは実装したが、運用方針（外部の検索APIに依存しない）により削除。審査記録は docs/audit/2026-11-05/ に残す

## HTTP API の厳格モード（2026-11-06）

SearXNG 互換の動作として、`engines=` に存在しない検索元を指定しても黙って既定の集合へフォールバックしていた。 `strict_engines=1` を付けると、存在しない名前は `unknown engines: ...` エラーになって黙らない。デフォルトは従来どおり（フォールバック）。

## 既定ログレベル（2026-11-06）

既定のログフィルタを `info,rustxng=debug` から `info` に変更した。debug はエンジン名やエラー文（クエリURLを含み得る）を日誌に書くため、既定で書かれるべきではない。デバッグ時は `RUST_LOG` で明示的に opt-in する。

## MCP のペイロードとトークン上限

同じ検索結果 100 問を、生の HTTP JSON と compact 形式で比較した。

| 形式 | 中央値バイト | 中央値トークン (cl100k_base) |
| --- | ---: | ---: |
| 生の JSON | 9,978 | 2,429 |
| compact | 6,433 | 1,542 |

compact形式はバイト数を約36%減らし、1000件のURLと先頭80文字を保持した。4096トークン制限時の先頭80文字の保持はcl100kで997件、o200kで1000件だった。トークン計数は `cl100k_base` / `o200k_base` を明示した場合に提供し、対象は structured JSON に限定する。
