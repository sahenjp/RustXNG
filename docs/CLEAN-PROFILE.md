# クリーン構成（公開APIと自前クロールを中心とした構成）

`settings.clean.toml` は、公開されているAPIと利用方針を持つプロバイダーを許可リストで選び、その他の検索先を除外する構成です。
一般Web検索のHTML取得（Google・Bing・DuckDuckGo など）は利用しません。足りない分は自前のインデックス（`rustxng-index`、robots.txt に配慮したクロール）で補います。
**`clean` は法的な適合性の認定ではありません。** 公開APIでも商用利用、検索結果の保存・再配信、帰属表示、クォータは個別に確認する必要があります。記録と未確認事項は[プロバイダーの利用条件](PROVIDERS.md)・[台帳](providers.csv)を参照してください。

2026-11-05: Standardも条件を記録した取得先だけに絞りました。Cleanはその中の小さい許可リストと、より保守的な全体送信間隔を使います。PyPIのHTML検索とキーが必要なOpenAlexは許可リストから外しました。以下の過去の測定は当時の設定の記録です。

## 何を有効にしているか

`[search] engine_allowlist` には**21件**の検索元を列挙しています。実際の動作・応答にはAPIの制限や環境が影響します。別に自前のインデックスを2種類指定できます（文書クロールの`index-docs`と、Wikipediaダンプの`index-wikipedia`）。ディレクトリが存在しなければ、その索引は利用されません（[Wikipedia索引](WIKIPEDIA-INDEX.md)）。許可リストは表示名で照合します（`mediawiki`のような内部型IDは共有されるため使用しません）。

| 種別 | エンジン |
| --- | --- |
| Wikimedia 系 | wikipedia, wikipedia any words, wikidata, wikibooks, wikinews, wikiquote, wikisource, wikispecies, wikiversity, wikivoyage, wiktionary, wikicommons |
| 開発者向け | github, stack overflow, crates.io, npm |
| 学術 | arxiv, crossref, semantic scholar |
| 地図・画像 | openstreetmap, openverse |

あわせて次の設定を入れています。

- `identified_ua = true`: 固定の名乗り（`rustxng/<版> (+https://github.com/sahenjp/RustXNG[; 連絡先])`）で送る。ブラウザを装う User-Agent は使わない
- `host_spacing_ms = 1100`: 同じホストへの送信間隔を 1.1 秒以上あける。Wikipedia だけは `[outgoing.host_spacing_overrides]` で 200 ms（Wikimedia は API の読み取りに固定の上限を設けていない。1 つの質問で Wikipedia に 3 回問い合わせるため、1.1 秒ずつ待つと応答が 2 秒を超えていた）
- `official_sites_wait_ms = 1500`: Wikidata から公式サイトを引く問い合わせを、エンジンが終わった後も 1.5 秒まで待つ（既定 400 ms）。Web 検索がないので、公式サイトにたどり着く手段がほぼこれだけのため
- `autocomplete = ""`: オートコンプリート用の上流呼び出しを止める
- `local_index_path = "index-docs"` / `local_index_merge = true`: 自前インデックスを併用する（シードは `bench/clean-profile/seeds.txt`・`seeds-devdocs.txt`・`seeds-ja.txt`）
- `contact = ""`: 運用者の連絡先。**公開運用では必ず入れてください**

起動: `rustxng --profile clean`（バイナリに組み込み済み。`rustxng --config settings.clean.toml` でも同じ）

**2026-11-04 の構成別再測定（clean: SealQA hit@10 = 123/254、技術文書100問 hit@10 = 61/100）は[比較レポート](COMPARISON-2026-11-04.md)にあります。** 以下の119/254などは2026-11-03の旧測定記録で、最新測定に置き換えないでください。

## 自前クローラーの強化点

詳細は `docs/LOCAL-INDEX.md`。要点は次のとおりです。

- RFC 9309 の robots.txt（最長一致、`*` と `$`、自分のグループ優先、取得不能ならそのホストを取得しない）と `Crawl-delay`
- 名乗る User-Agent、ホストごとの間隔とページ上限、`Retry-After` の尊重
- `noindex` / `nofollow`（meta と `X-Robots-Tag`）、同一サイト内のリダイレクトのみ追従
- URL 正規化、canonical（同一ホストのみ）、本文ハッシュによる重複除外
- ホスト単位のスケジューラ（混んだホストが他を待たせない）

検索側はタイトル（×3）、URL の語（×1.5）、フレーズ（×2）を加点し、スニペットを返します。さらに、長い質問がストップワードだけで無関係なページに当たらないよう、**内容語の約 3/5 以上が一致したページだけ**を返します（後述）。

## 測定

条件: SealQA（seal_hard + seal_0 の重複を除いた 254 問）、質問をそのまま送る、LLM なし、直列、1.5 秒間隔、新規起動のサーバー 1 つ。採点は正規化後の URL 完全一致。
自前インデックスは `bench/clean-profile/seeds.txt` の 16 シード（一般的なドキュメントサイト）から **3,635 ページ**（ホスト上限 300、深さ 4、遅延 1 秒）。ベンチマークの正解 URL はシードに使っていません。
クロール結果: 3,635 ページ登録。robots.txt で 28 件、noindex で 14 件、本文重複で 229 件、ホスト上限で 44,420 件を除外。取得失敗 209。バックオフ 0。

### 段階ごとの測定と、そこで直したこと

| 段階 | hit@10 | MRR@10 | 中央値 | 備考 |
| --- | ---: | ---: | ---: | --- |
| API のみ（Wikipedia が `?curid=` 形式の URL を返す） | 0 | 0 | 0.75 s | 採点が URL 完全一致のため、Wikipedia の正解は構造上取れなかった |
| + 自前インデックス（修正前） | 0 | 0 | 0.86 s | 技術文書が上位 10 件の平均 6.3 件を占め、Wikipedia の結果を押し出していた |
| + 内容語フィルタ | 0 | 0 | 0.86 s | 占有は 0.27 件に低下。URL 形式の問題は残ったまま |
| + Wikipedia を `/wiki/<題名>` 形式に + 長文質問の語を絞る | 37 | 0.110 | 0.76 s | |
| + 固有名を引用符で探す `wikipedia_entities`（3 件目として併用） | 83 | 0.223 | 1.65 s | 許可リストには入れていない（下記） |
| + いずれかの語に一致する `wikipedia any words` | 102 | 0.253 | 2.0 s | |
| **+ Wikipedia ダンプのインデックス（618 万記事、3.0 GB）（現在の構成）** | **119** | **0.311** | **2.1 s** | 結果ゼロが 13 → 0 |

直した点:

1. **Wikipedia エンジンが返す URL を `/wiki/<題名>` にしました。** `?curid=` では他のエンジンの URL と重複判定できず、読む側にも分かりにくいためです。
2. **長い英文の質問は、話題語だけに絞ってから Wikimedia 系の検索にかけます**（疑問詞・冠詞・前置詞を除く。短い質問、引用符、演算子、英語以外は変更しません）。MediaWiki 検索は全語一致なので、文のままだと何も返りません。
3. **`wikipedia any words` を追加しました。** 話題語を `OR` でつないで、一致する語が多いページから返します。Wikipedia 正解 50 問の診断では、全語一致の上位 10 件に正解が入ったのが 17 問、`OR` 形式は 34 問でした。
4. **自前インデックスは、内容語の約 3/5 以上が一致したページだけを返します。** OR 一致だと "the" や "of" だけで当たってしまうためです。

注意:

- **評価データでの試行錯誤があります。** 診断スクリプトで検索の形を比べた質問は、最終評価と同じ SealQA の質問です。手法自体は一般的な書き換えで、正解 URL は使っていませんが、数字は多少よく出ている可能性があります。別の質問集での確認が望ましいです。
- **`wikipedia entities` は実装済みですが、クリーン構成の許可リストには入れていません。** 3 件目にすると、同じホストへの送信間隔（1.1 秒）のせいで 3 秒の締め切りを超え、結果が空になる質問が出ました。有効にするなら `timeout_limit` を延ばしてください。
- **ダンプのインデックスの重みを 1.0 から 2.0 に上げても変わりませんでした**（hit@10 は 119 のまま、MRR は 0.307）。1.0 のままです。
- **遅くなっています。** 応答は約 0.8 秒から 2 秒になりました。Wikipedia に 2 回問い合わせ、同じホストへは 1.1 秒あけるためです。礼儀を優先した結果です。

### 「Suspended: Unexpected error」の正体

中央値 4 つのエンジンがこの表示になっていましたが、障害ではありませんでした。
質問文が長いと wikidata・wikispecies・wikivoyage などは空の結果を返します。空の応答が 8 回続くと 5 分休ませる仕組み（`empty_result_limit`）が働き、その休止中の表示が誤って「Unexpected error」になっていました。
表示を「Resting: no results lately」に直しました。休止の仕組み自体は意図どおりの動作です。

### 既知の限界

- 上記の最終測定では結果ゼロの質問は0問でした。途中段階や索引なしの環境では0件応答が発生することがあります。
- 非 UTF-8 のページは、不正な文字を置換して取り込みます。
- 天気の回答（open-meteo）と一部のプラグインは、この構成の対象外です。
- 本表は 1 回の実行です。外部 API の状態で数問は変わりえます。
- 通常構成（`settings.toml`）は 2026-11-04 に測定しました（hit@10 128/254、`docs/PROVIDERS.md`）。

## 結論

この旧測定のクリーン構成は、SealQAの参照ページhit@10が119/254（46.9%）で、旧構成156/254の約76%でした。2026-11-04の新測定は123/254（48.4%）です。一般Web検索を使わないため、Wikipedia以外に参照ページがある質問、専門文書・日本語公式サイトの検索に弱さが残ります。
自前インデックスの追加・改善に加え、適切な許諾を確認した正式APIの導入などを検討できます。旧測定は1回の観測であり、あらゆる利用環境での性能を保証するものではありません。
