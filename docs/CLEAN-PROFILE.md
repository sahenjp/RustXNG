# クリーン構成（`--profile clean`）

> **外部の検索に一切依存しない構成です。** 実行時に外部の検索プロバイダーへ問い合わせません。
> 自前の索引（クロール索引とWikipediaダンプ索引）だけが情報源です。

## 構成

```text
rustxng-index crawl   →  Tantivy索引（BM25）   ← 自前クロール
rustxng-wikidump       →  Tantivy索引            ← 公式ダンプから構築（WIKIPEDIA-INDEX.md）
      ↓
rustxng --profile clean  →  ローカル索引だけを検索
```

- **外部エンジン 0**。`use_default_settings = false` で組み込みのエンジン一覧を置き換え、検索エンジンは走らない
- **検索はオフラインで動く**。事前に作った索引から検索し、外部の検索プロバイダーへ問い合わせない。ただし、索引の作成・更新には取得元への通信が必要で、明示的な本文取得などの別機能は外部通信を発生させ得る
- 自動補完なし（打鍵ごとの外部送信をしない）
- 公式サイトのWikidata参照も無効（外部通信をしないため）

## 使い方

```bash
# 1. 索引を作る（docs/LOCAL-INDEX.md、docs/WIKIPEDIA-INDEX.md）
rustxng-index crawl --seeds seeds.txt --out ./index-docs --max-pages 5000

# 2. 起動
rustxng --profile clean
```

索引ディレクトリが無ければ、その索引は何も返さない（エラーにはならない）。

## 検索元の指定と索引の更新

`engines=local_index` またはクエリの `!local_index` で、自前索引だけを検索できます。
`wikipedia_index` と組み合わせることもできます。明示指定時は、指定外のプロバイダーや索引を追加しません。
索引が利用できない場合は、外部検索に切り替えずエラーを返します。
ドメイン制限はローカルの上位候補を選ぶ前に適用し、`pageno` によるページ送りに対応します。

再クロールは同じURLの文書を置き換え、取得時に判明した `noindex`・404・410を反映します。
サイトマップを含む接続先の公開IP検査、リダイレクトごとのrobots確認、探索数と待機キューの上限を適用します。
具体的なコマンドと互換性は[自前インデックス](LOCAL-INDEX.md)を参照してください。

## 測定結果の読み方

上の数値は、外部検索プロバイダーを呼ばず、準備済みのローカル索引だけで測った値です。40ms台の中央値は測定時の環境での記録で、初回起動や索引構築時間を含みません。

公開APIも使っていた旧Clean（2026年11月4日、SealQA hit@10=123/254）とは検索先が違います。単純な前後比較でコードの改善・劣化を判断できません。索引のシードには正解ページに関係するサイトが含まれており、未知のサイトや最新情報の検索性能を保証しません。[保存済みの測定結果](../bench/results/profiles-2026-11-05/clean/sealqa/)を参照してください。

## 内容についての注意

- クロールは robots.txt（RFC 9309）に従い、名乗るUser-Agentで行う
- WikipediaダンプはWikimedia財団が提供する公式アーカイブ（CC BY-SA 4.0）。再利用時の帰属が必要
- **「クリーン」は内容の許諾を保証しない。** 各サイトのライセンスが本文の再利用を律する
