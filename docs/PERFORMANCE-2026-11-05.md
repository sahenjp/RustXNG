# Standardプロバイダー見直しと性能測定（2026-11-05）

最新mainの`5f0ae3b`（v0.28.0）を作業ブランチに取り込んだ`b986b79`を基点とします。
測定機はLinux x86_64、Rust 1.99.1です。結果を全環境で保証するものではありません。

## 同時キャッシュミス

外部サービスを使わず、応答40ms・同一ホストの送信間隔20msのローカルHTTPサーバーで測定しました。
16並列リクエストを5回実行し、各回でクライアントとキャッシュを作り直しました。
変更前は`src/network.rs`と`src/cache.rs`だけを基点へ戻し、同じ依存関係と測定コードで比較しています。
ビルド設定はdevで、リリース環境や実際のインターネット検索の倍率を示す測定ではありません。

| リクエスト | 変更前の中央値 | 変更後の中央値 | 上流への送信回数（各回） |
| --- | ---: | ---: | --- |
| 同一内容16本 | 342.98ms | 43.74ms | 16回 → 1回 |
| 異なる内容16本 | 342.18ms | 343.09ms | 16回 → 16回 |

同一リクエストの同時キャッシュミスでは所要時間を約87%削減しました。
別々のリクエストは並列実行を保っています。生データは
[cache-contention.json](../bench/results/provider-policy-2026-11-05/cache-contention.json)にあります。

```bash
cargo run --locked --example cache_contention
```

待機するリクエストは各自の期限を持ち、短い期限の呼び出しで長い期限の呼び出しを中断しません。
失敗はキャッシュせず、先行処理がキャンセルされた場合は次の呼び出しが再試行できます。
ヘッダー・Cookie・フォーム・JSON・プロキシの違いをリクエストの識別に含めています。
送信間隔の待機と通信にも共通の期限を適用し、合計でタイムアウトを超える問題を修正しました。

集約は同じCacheを使うプロセス内に限ります。Valkeyを共有してもプロセス間の送信調整は行いません。

文書索引では、英字とCJKを混ぜた検索で英字の用語を少なくとも1つ必須にします。
これにより「nginxの設定」が別製品の日本語マニュアルだけを拾う問題を抑え、
CJK文字を含まない英語の該当マニュアルも候補にできます。
百科事典のloose検索は、翻訳された名称を探すため従来の条件を保ちます。
同じ文書索引と100問を使ったオフライン評価では、hit@1が21→22、hit@5が25→27、
MRR@10が0.228611→0.240611でした。順位が変わったのは2問で、順位の悪化はありませんでした。
この数値はローカル索引だけの評価で、検索全体の評価とは区別してください。
[候補URLと評価記録](../bench/results/provider-policy-2026-11-05/local-index-quality.json)を保存しています。

```bash
cargo run --locked --example local_quality -- index-docs bench/quality-questions-100.json
```

## Standardの検索品質

変更後のリリースバイナリで既存の100問を実行しました。
この変更後の測定では、除外対象のプロバイダーへ問い合わせていません。
質問や正解URLは変更していません。質問間の待機は1.1秒です。
ローカルの文書索引41,144件とWikipedia索引6,185,457件を使用しました。

同日に追加された[変更前構成の測定記録](audit/2026-11-05/standard-baseline-2026-11-05.md)も照合しました。
質問と正解URLが一致し、測定用設定は11系統の有効・無効以外が現在の同梱設定と一致することを確認しました。
記録上は同じv0.28.0系のバイナリとローカル索引を使い、約20分の時間差で測定しています。
最終測定には、その後の混在検索の修正も含まれます。

| 指標 | 同日・11系統有効の構成 | 2026-11-05の変更後Standard |
| --- | ---: | ---: |
| hit@1 | 70/100 | 55/100 |
| hit@5 | 84/100 | 69/100 |
| MRR@10 | 0.762 | 0.610 |
| 中央値 | 981.3ms | 826.3ms |
| HTTPリクエストエラー | 0 | 0 |

**検索品質の維持は未達です。** 同日の記録では検索全体の中央値は約16%短くなっていますが、
上流の応答は測定時刻によって変わります。差の全てをプロバイダー無効化やコード修正の効果とは断定できません。
同時キャッシュミスの高速化を、一般検索の品質向上として扱わないでください。
2026-11-04の保存済みStandardは72/100・87/100・660.3msでしたが、索引や上流の状態が異なり得るため、
今回の変更前後の比較表では同日の追加測定を使用しています。

現状の公式APIとローカル索引だけでは、除外した広域検索の範囲を十分に補えていません。
品質維持には、許諾を確認した広域検索APIの設定、または用途に合う自前索引の拡充が必要です。

混在検索の修正前の実測はhit@1=55、hit@5=68、MRR@10=0.608、中央値807.0msでした。
[修正前の全応答](../bench/results/provider-policy-2026-11-05/docs100-initial.json)も残しています。
こちらも上流の変動を含むため、差を索引の修正だけの効果とは断定できません。

[全100問の応答・URL・順位](../bench/results/provider-policy-2026-11-05/docs100.json)と
[測定条件](../bench/results/provider-policy-2026-11-05/metadata.json)を保存しています。

`cargo fmt --all --check`、Pythonのテスト、プロバイダー台帳の整合チェックとStandardポリシーチェックを実行しています。
